## 一、产品概述

### 1.1 问题
现代人日均手机解锁次数超 80 次，连续使用时长极易在无意识中突破 2–3 小时，尤其夜间躺床场景，刷短视频、社交媒体常远超预期，影响睡眠与次日状态。

### 1.2 产品定位
一个**无需主动操作、安装即自动运行、以提醒为核心**的防沉迷工具。目标是**帮用户意识到并减少无意识刷机**，而不是把用户"关起来"。

- 计时到阈值 → 顶部横幅提醒（软提醒，30 秒自动消失，无交互按钮）
- 计时到上限 → 锁屏倒计时提醒（30 秒倒计时结束后执行 `lockNow()`）
- 用户用手机自带锁屏解锁后继续使用
- **全程不设置任何绕过障碍**：提醒到位即达成使命
- **特定使用情景下完全静默**：通话中、开车导航中由软件自动识别，不打扰

### 1.3 核心价值主张
- **自动**：装好即运行，无需手动开启服务
- **提醒**：到点顶部横幅提醒 + 锁屏倒计时，让用户"被看见"自己的使用时长
- **懂情景**：通话、开车导航时自动静默，避免误伤正当使用
- **零成本**：纯本地、免费、不需要任何服务器

## 二、核心概念定义

| 术语 | 定义 |
|-----|------|
| **使用中** | 屏幕亮起 → 计入连续使用时长；屏幕息屏 → 计时器重置为 0 |
| **连续使用** | 从最近一次屏幕亮起开始累计，中途息屏即清零重来 |
| **监控时段** | 固定 0:00-24:00（全天），用户通过开关控制启用/停用。计时始终运行不受开关影响，开关仅控制提醒功能是否生效 |
| **首次提醒** | 连续使用达阈值时在屏幕顶部弹出横幅提醒，30 秒后自动消失，无交互按钮。内容为休息提醒 |
| **锁屏提醒** | 首次提醒后继续使用达阈值时，在屏幕顶部弹出锁屏倒计时横幅（30 秒倒计时），倒计时结束后执行 `DevicePolicyManager.lockNow()` |
| **计时重置** | 锁屏提醒执行 `lockNow()` 后计时器归零 |
| **豁免场景** | 特定使用情况下列为"不打扰"，计时暂停、不触发提醒/锁屏。由软件**自动识别**，用户零配置。V1 含：**通话中、开车导航中** |
| **今日使用** | 仅记录被软件强制锁屏的会话时长，用户主动锁屏或自动息屏不记录。多次强制锁屏的时长累加计算，精确到秒（中文单位） |

## 三、功能需求

### 3.1 功能清单

```
核心功能（必须）
├── 🔢 连续使用计时器
│     · 屏幕亮起 → 开始计时
│     · 屏幕息屏 → 计时清零
│     · 息屏 ≤ 10 秒再亮 → 视为同一次，计时不清零（防作弊）
│     · 格式：时:分:秒（与现实世界时间流速一致）
│     · 计时始终运行，不受监控开关影响
├── 🔔 分级提醒机制
│     · 首次提醒（软提醒）：连续使用达阈值 → 屏幕顶部横幅 30 秒后自动消失
│     · 锁屏提醒（强提醒）：首次提醒后继续使用达阈值 → 屏幕顶部横幅 30 秒倒计时 → lockNow()
│     · 两次提醒均为顶部横幅样式，无交互按钮，30 秒后自动消失
│     · 监控开关关闭时提醒不触发
│     · 进入监控时段时以当前累计计时为基准计算提醒触发点
├── 🔒 锁屏提醒
│     · 调用 lockNow()，屏幕立即锁定，作为"到点了"的最强信号
│     · 不是惩罚，是提醒；用户随时可解锁
├── 📞 豁免场景（软件自动识别，用户零配置）
│     · 通话中：来电 / 去电 / 通话进行中 → 计时暂停
│     · 开车导航中：检测到导航 App 前台运行或车载蓝牙连接 → 计时暂停
│     · 豁免期间即使达阈值，也不弹提醒、不锁屏
│     · 豁免结束后恢复计时（从暂停点继续）
├── ⚙️ 权限引导
│     · 首次安装弹出设备管理器权限授权框
│     · 后续在设置界面提供 ROM 保活引导文案
└── 🏠 主页界面
      · 显示连续使用时间（时:分:秒，蓝色文字）
      · 显示监控时段（00:00 - 24:00）及生效状态
      · "今日使用"：仅统计强制锁屏的会话时长，精确到秒（中文单位），累加计算
      · "解锁次数"：监控时段内的亮屏次数

重要功能（建议）
├── 📊 每日使用报告：当日总时长 / 最长连续使用 / 解锁次数（本地统计）
├── 📅 近 7 天使用报告（初始为空，次日开始显示前一天数据）
├── 🔔 通知栏常驻计时显示：显示当前连续使用时长
└── ⚙️ 自定义提醒阈值：首次提醒（≤360 分钟）、锁屏提醒（≤180 分钟），不能为 0/小数/负数

辅助功能（可延后）
├── 🎨 深色模式（跟随系统）
└── 📤 数据导出
```

### 3.2 豁免场景检测说明（工程必读）

> **设计原则：豁免场景由软件自动识别，用户零配置。** 用户不需要手动添加"通话""导航"或任何其他环境——App 通过系统信号（通话状态、蓝牙连接、前台 App）自动判断当前是否处于豁免情景。

| 豁免场景 | 检测方式 | 所需权限 | 备注 |
|--------|--------|--------|------|
| 通话中 | `TelephonyManager` / `PhoneStateListener` 监听 `CALL_STATE` | 无额外权限（READ_PHONE_STATE 基础权限） | 稳定可靠 |
| 开车导航中（方案 A） | `UsageStatsManager` 查询前台 App，匹配导航 App 包名（高德/百度/腾讯/Google 地图） | `PACKAGE_USAGE_STATS`（需用户在设置中手动授予） | 检测准，但权限授予体验差 |
| 开车导航中（方案 B） | 监听车载蓝牙连接（`Bluetooth` / `BluetoothDevice` 广播） | `BLUETOOTH` / `BLUETOOTH_CONNECT` | 授权简单 |
| 开车导航中（推荐） | **A + B 组合**：导航 App 前台 **或** 车载蓝牙连接，任一满足即豁免 | 见上 | 覆盖更全 |

### 3.3 明确不做的功能

| 功能 | 不做原因 |
|-----|--------|
| 紧急解锁密码 | 锁屏仅为提醒，用户用自有锁屏解锁即可，额外密码多余 |
| 应用白名单（用户自选列表） | 改为"豁免场景"机制，由软件按使用情况自动判断，用户零配置 |
| 家长管控模式 | 零预算，无云端，留后续版本 |
| 云端账号 / 登录 | 纯本地存储已足够 |
| 社交 / 排行榜 | 非核心，增复杂度与合规风险 |
| iOS 版本 | Android V1 稳定后再规划 |
| 真关机 | Android 系统封堵，需厂商签名，不可行 |
| 监控服务启动/停止开关 | 安装即自动运行，无需用户手动操作 |

## 四、分级提醒机制（核心流程）

### 4.1 状态机

```
[空闲] ──屏幕亮起──→ [计时开始]
                                │
                                │ 连续使用达首次提醒阈值（用户自定义）
                                ↓
                     [首次提醒 ⚠️]  （顶部横幅 30 秒后自动消失，无交互按钮）
                                │
                                │ 继续亮屏，累计达锁屏提醒阈值
                                ↓
                     [锁屏提醒 🔒]（顶部横幅 30 秒倒计时）
                   倒计时结束 → lockNow() → 屏幕锁定（强提醒）
                                │
                                │ 用户用自有锁屏解锁
                                ↓
                     [计时归零，正常使用]

[豁免分支]
  进入通话 / 开车导航 ──→ [计时暂停，不触发任何提醒]
                         │
                         │ 豁免结束（通话结束 / 退出导航 / 断开车载蓝牙）
                         ↓
                      [恢复计时，从暂停点继续]

[监控开关关闭]
  计时继续运行，但不触发任何提醒
  开关重新打开 → 以当前累计计时为基准重新计算提醒触发点
```

### 4.2 提醒分级详情

| 阶段 | 触发条件 | 方式 | 内容示例 | 持续时间 |
|-----|--------|------|--------|--------|
| 正常计时 | 屏幕亮起 | 无打扰 | 通知栏显示当前时长 + 主页实时计时 | — |
| 首次提醒 | 连续使用达用户设定的首次提醒阈值 | 屏幕顶部横幅（无交互按钮） | "😴 已连续使用 X 小时 X 分钟了，休息一下吧" | 30 秒自动消失 |
| 锁屏提醒 | 首次提醒后连续使用达用户设定的锁屏阈值 | 屏幕顶部横幅（含动态倒计时数字）+ 倒计时结束执行 `lockNow()` | "亲爱的，你已经严重超时使用手机了呢，手机将在 30 秒后锁屏哦！" | 30 秒倒计时 → 锁屏 |
| 豁免中 | 通话中 / 开车导航中 | 无 | 通知栏显示"豁免中，已暂停提醒" | 不受影响 |
| 解锁后 | 屏幕重新亮起 | 无 | 正常可用 | 计时器归零 |

> **设计原则**：提醒到位即达成使命，不在解锁路径上设置任何额外障碍（无密码、无二次确认）。两次提醒均为顶部横幅样式，类似短信通知，不遮挡主界面交互。

## 九、边界情况处理

| 场景 | 处理方式 |
|-----|--------|
| 息屏 ≤ 10 秒再亮 | 视为同一次，计时不清零 |
| 息屏 > 10 秒再亮 | 计时清零，从头开始 |
| 通话 / 开车导航中 | 计时暂停、不提醒、不锁屏；结束后恢复计时 |
| 手机重启 | 服务随系统自启动恢复，计时归零 |
| 监控开关关闭 | 计时继续运行，提醒不触发；重新开启后以当前累计计时为基准计算提醒触发点 |
| 修改提醒阈值 | 重置提醒标记，以修改时刻的累计计时为基准重新计算 |
| OTA 更新 | 保留所有配置和数据 |

## 附录 A：Android 技术要点速查

| 问题 | 答案 |
|-----|------|
| 锁屏/提醒 API | `DevicePolicyManager.lockNow()` |
| 所需权限 | `BIND_DEVICE_ADMIN`（Device Administrator） |
| 权限如何授予 | 首次安装跳转系统授权页，用户手动勾选 |
| 通话状态监听 | `TelephonyManager` / `PhoneStateListener` |
| 导航状态检测 | 前台 App 检测（`UsageStatsManager`，需 usage-stats 权限）或 车载蓝牙连接（`Bluetooth`） |
| 能真关机吗 | 不能，需系统/厂商签名 |
| 后台被杀怎么办 | 引导加入电池白名单 + 开启自启动 |
| 数据存哪 | SharedPreferences + Room（纯本地） |
| 需要服务器吗 | 不需要，V1 零成本 |
| 计时器格式 | `时:分:秒`，与现实世界时间流速一致 |
| 今日使用统计 | 仅统计被软件强制锁屏的会话，累计累加，精确到秒（中文单位） |
| 提醒样式 | 屏幕顶部横幅，30 秒自动消失，无交互按钮 |
